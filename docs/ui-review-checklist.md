# UI Review Checklist

모든 화면·연출 변경(`[UI]`, `[Scene]`, `[Interaction]`)과 merge 후 `origin/main` 상태를
동일한 잣대로 심사하기 위한 기준 문서. 세션이 바뀌어도 같은 기준으로 리뷰되게 하는 것이 목적.

- 심사 관점: **플레이어 가치**(첫 만남에서 읽히는가, 조작이 보이는가) > 내부 구현 아름다움.
- 레퍼런스 기준: Hades, Dead Cells, Elden Ring 등 검증된 액션 로그라인 연출 수준을 하한으로 삼아,
  "대충 만든 느낌(조잡한 연출)"이 main에 누적되지 않게 한다.
- 우선순위: `P0` 차단(PR 요청 변경), `P1` 요청 변경 또는 즉시 후속 이슈, `P2` 후속 이슈.

## 에이전트 오딧 루틴

### 1차: merge 전 PR 심사 (차단)

P0 판정은 반드시 merge 전에 내린다. main에 이미 합류된 뒤에는 차단할 수 없기 때문이다.

1. UI가 보이는 PR이면 리뷰 시점에 `ui-previews` 브랜치의 해당 PR 캡처를
   **이미지로 직접 검수**하고, PR diff와 아래 A~J 체크를 통과시킨다.
2. 캡처가 없거나, 변경된 UI가 실제로 노출될 수 있는 상태의 캡처(예: 전투 UI면
   최저 밝기 씬·피격 순간·모바일)가 빠졌으면 P0. `UI capture contract` 자동 검사에는
   캡처 불가 예외가 없으므로 사유 기록만으로 CI가 통과하지 않는다 — 렌더링 가능한
   환경(웹 프리뷰 아티팩트 스크린샷, godot-mcp 뷰포트 PNG 등)에서라도 캡처를 반드시 확보한다.
   변경 화면과 무관한 상태는 요구하지 않는다.
3. 코드 diff에서 토큰·상수 준수 여부 확인 (E 섹션).
4. 위반은 PR 코멘트 또는 후속 이슈로 남긴다. 판정 근거는 캡처 URL + 파일:라인 을 함께 인용한다.

### 2차: merge 후 main 스윕 (비차단 안전망)

merge 직후 `git log origin/main` 으로 신규 유입 diff를 훑어 1차에서 놓친
위반을 수집한다. 발견분은 즉시 후속 이슈로 전환하며, 이미 합류된 변경은
revert 여부만 별도 판단한다.

## A. 가독성 & 대비 — P0

- [ ] 터치 컨트롤(버튼 링, 아이콘, 스틱)이 배경 대비 **3:1 이상**
      (WCAG 1.4.11 non-text contrast 준용).
- [ ] 본문 텍스트 4.5:1 이상, 24px+ 굵은 텍스트 3:1 이상.
- [ ] 반투명 UI가 어두운 씬 위에서 사라지지 않는지 캡처로 확인
      (최악 케이스: 야외 밝기 낮은 씬 + 비네트 겹침).
- 검증 도구: ImageMagick / Pillow + wcag-contrast-ratio로 캡처 PNG 대비 산출.
- 알려진 위반(2026-08-23 오딧): 터치 공격·회피 버튼이 씬에 묻힘
  (`ui-previews` pr-534 `controls-touch-natural-copy`).

## B. 세이프에어리어 & 터치 타깃 — P0

적용 범위: 모바일·터치 레이아웃에 노출될 수 있는 UI. PC 전용 화면(데스크톱 창에서만
보이는 UI)에는 아래 모바일 마진을 강제하지 않는다.

- [ ] 960x540 기준 좌우 `60px` / 상 `24px` / 하 `34px` 이내 침범 금지 (AGENTS.md 기본값).
- [ ] 핵심 터치 컨트롤은 좌우 `72px` / 하 `58px`, 바텀 CTA는 하단 `40px` 이상 확보.
- [ ] `test_id` / `uat_action` 계약 유지 (`scripts/verify_ui_automation_contract.py` 통과).
- [ ] 이동 시 `scripts/ui/mobile_safe_area.gd` 상수 재사용, 애드혹 오프셋 금지.
- 검증 도구: godot-mcp-runtime UI discovery(Control 지오메트리 덤프)로 마진 자동 계산.

## C. 모션 & 게임필 — P1

- [ ] 히트스톱 위계 유지: 일반 타격(0.03s) < 강공격·피격(0.05~0.06s), 스케일 0.08~0.15.
      새 프로파일 추가 시 기존 위계와 비교 근거 필요 (`player.gd` `hit_stop_profile`).
- [ ] 데미지 숫자·코치마크 등 펀치 스케일/duration이 스타일 위계를 반영
      (ordinary < power < player_damage < parry).
- [ ] 연출 tween의 `set_ignore_time_scale(true)` 여부가 의도와 일치하는지
      (히트스톱 중 같이 멈출 연출인지, 계속 흘러야 하는지 명시).
- [ ] reduced-motion 설정을 존중 (`OnboardingVisualTokens.motion_duration` 패턴 준수).

## D. 피드백 강도 — P1

- [ ] 화면 전체 이펙트(비네트, 플래시) 피크 알파 **0.55 이하** 권장.
      레퍼런스 하한: Hades/Elden Ring 피격 피크 0.3~0.5.
      현재 값(0.78)은 과강 — 저체력 상시 오버레이(0.48)와 겹칠 때 누적 확인 필수.
- [ ] 동일 이벤트의 다중 피드백(사운드+비네트+히트스톱+숫자)이 합산 과다가 아닌지.
- [ ] 강공격이 일반 공격보다 "체감상" 확실히 강해야 함 (숫자 크기·색·사운드·히트스톱 종합).

## E. 토큰 & 일관성 — P1

- [ ] 새 UI 코드는 `OnboardingVisualTokens` / `DungeonUiTheme` 재사용.
      하드코딩 `Color(...)`는 토큰에 없는 색임을 주석으로 근거 남긴 경우만 허용.
- [ ] 코치마크·패널·버튼 스타일이 기존 화면과 동일 (모서리 반경, 보더 1px, 잉크 배경).
- [ ] 기존 팔레트에서 채도·명도 급변 색 도입은 디자인 근거 필요
      (예: minimap start 홈 아이콘의 녹색은 팔레트 이탈 — 허용하려면 문서화).

## F. 정보 설계 & 온보딩 — P1

- [ ] 내부 수치·디버그 값을 플레이어에게 노출 금지 (PR #534 선례: "방 안을 돌아봐" 정제).
- [ ] 안내 문구는 행동 중심 + 플랫폼별 입력 표기(PC/터치 분기).
- [ ] 미탐험·숨김 상태가 "미완성"처럼 읽히지 않게 표현.
      알려진 위반: minimap 미탐험 방의 회색 `?` 박스 → 실루엣 아이콘/점선 테두리로 교체 검토.
- [ ] 모든 온보딩 흐름에 건너뛰기 경로 제공 ("안내 건너뛰기").

## G. 한국어 타이포그래피 — P2

- [ ] `UiFontRoles` 적용, Label별 폰트 파일 개별 로드 금지.
- [ ] 한글 말줄임·줄바꿈이 어색하지 않은지 (조사 떨어짐, 어미 잘림 없음).
- [ ] 숫자·단위 표기 일관 (데미지, 체력, 시간).

## H. 색각 접근성 — P2

- [ ] 색만으로 상태를 구분하지 않음 (모양·아이콘·위치 병행).
- [ ] 적록 색약 시뮬 캡처 스폿체크 (ImageMagick 채널 믹싱으로 대체 가능).

## I. 성능 & 오버드로 — P2

- [ ] 풀스크린 ColorRect/ShaderMaterial 남발 금지, CanvasLayer 레이어 상수
      (`RenderLayers.UI_SESSION_LAYER` 계열) 재사용.
- [ ] 파티클·페이드 연출이 Web 빌드 프레임 하락을 유발하지 않는지 스폿체크.

## J. 캡처 증거 — P0 (프로세스)

- [ ] UI PR 본문에 `## UI 캡처` + raw URL (`docs/pr-hygiene.md` 규칙).
- [ ] 최악 케이스 상태 포함(변경 UI가 그 상태에 노출될 때만):
      전투 화면이면 최저 밝기 씬·피격 순간, 터치 대상이면 모바일(960x540), PC 대상이면 1280x720.
- [ ] 캡처를 확보했는지 (자동 검사에 예외 없음 — 불가 환경이면 웹 프리뷰 아티팩트·godot-mcp 뷰포트 캡처로 대체).

## 도구 스택 (2026-08-23 리서치 결론)

| 용도 | 도구 | 비고 |
|------|------|------|
| 실행 중 게임 스크린샷·입력·UI 덤프 | `npx godot-mcp-runtime` (Erodenn) | 뷰포트 PNG, Control 이름 클릭, 지오메트리 덤프. 저장소 오염 없음 |
| 행동 계약 테스트 | gdUnit4 scene runner | 터치/키 입력 시뮬, `simulate_until_signal`. 스크린샷 API는 없음 |
| 대비 자동 검산 | ImageMagick / Pillow + wcag-contrast-ratio | 캡처 PNG 후처리 |
| 웹 익스포트 보조 검수 | gstack `/browse` | single-threaded export 한정, 입력 정밀도 낮음 — 시각 비교용 |
| ~~headless 캡처~~ | `--headless` | **렌더링 안 됨** — 캡처는 반드시 windowed 실행 |

## 위반 처리

- `P0`: PR 요청 변경 → 해소 전 merge 금지.
- `P1`: 요청 변경 또는 후속 이슈 즉시 생성 (assignee 지정).
- `P2`: 후속 이슈로 적립, 마일스톤 회의에서 묶음 처리.
